# 微信消息接收与知识整理：合成示例候选

`receiver.py` 和 `knowledge.py` 是依据现有程序职责写的最小示例，**不是生产代码快照、不是微信第三方接口协议实现，也不连接微信**。另有 `reference_snapshot/`：来自现网事件规范化模块的脱敏参考代码，去除了注释与文档字符串，不包含完整服务。目录没有真实账号、消息、群标识、令牌、服务器地址或业务数据库。

## 只读源码盘点

| 已核实的现网程序 | 职责线索和依赖 | 是否已纳入本目录 |
|---|---|---|
| `api_groupbot.py` | 微信接收服务入口；包含 HTTP 处理、SQLite 存储及运营编排，依赖 `wtapi_events`、`collection_policy`、`company_knowledge`、消息队列等多个内部模块。 | 未复制；文件较大且还需逐项审查配置、标识与传递依赖。 |
| `wtapi_events.py` | 群消息、私聊、媒体和 XML 相关的规范化，依赖 `defusedxml` 及项目内事件模块。 | 已收录脱敏参考及视频事件依赖，使用合成事件对照；不含接收服务或完整依赖。 |

当前只读盘点发现一份部署目录内的 `test_wtapi_resolver.py`，以及本地历史候选的蒸馏与受信文档测试文件；本轮只核对测试文件名称，没有读取其中可能含业务资料的 fixture，也没有把它们当成新示例的测试。正式公开前，需要单独审查这些文件及测试数据、外部依赖与许可证。已检查过的三份候选程序未命中一组常见邮箱、私网 IP、群 ID 和硬编码凭据模式；自动模式扫描不是人工隐私审查。

## 与生产的差异

- 示例只定义了合成 JSON 格式和注入式验签函数；测试中的 HMAC 是假设用的测试机制，不代表现有微信接口的认证方式。无 HTTP 监听、上游采集、账号登录、回调适配或主动发送。
- 显式策略按 `(account_id, conversation_id)` 控制提炼；未授权消息仍归档，但不加入知识队列。示例不自动为后来新增授权补排旧消息，也不反映现网完整授权规则。
- 相同来源消息 ID 与相同内容幂等；同一标识内容变化会拒绝。不同账号与会话不按显示名合并。
- 假提炼结果必须附有原文子串，且数据库事务不会跨提炼调用；有引用仍不保证结论逻辑正确。空提炼记为 `no_supported_facts`，失败不记成功；没有向量索引、真实 AI、模型微调、作业崩溃租约恢复或生产级数据保护。
- 示例数据库结构与生产库不同，不能指向或迁移现有数据库。它不会产生真实业务知识，也不能证明现网知识链路已完成。

## 测试

```sh
python3 -m unittest -v test_pipeline
python3 -m pip install -r requirements-test.txt
cd reference_snapshot && python3 -m unittest -v test_events
```

示例有 10 项合成测试；事件快照有 11 项合成测试，并已在隔离环境与原程序对照相同输入输出。未访问外部网络、真实微信数据或真实模型。实际系统的身份授权、数据覆盖、文档解析、向量检索和受控发送需要分别验收。
