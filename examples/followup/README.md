# 客户跟进列表：可公开的参考候选

本目录整理了一个按渠道、账号、来源范围和会话身份隔离的客户跟进列表，包含状态筛选、有限量分页、来源授权复核、并发状态变化检测、来源续查，以及响应式模板。测试使用临时 SQLite 数据库与虚构记录，不发送消息，不访问第三方账号。

**本目录不是可直接部署的生产系统。** 生产授权和渠道接入未随候选提供：`owner_inbox.NativeAuthority` 默认抛错，调用方必须明确注入来源适配器，并自行实现身份认证、权限收回、来源核对和业务应用的集成。模板继承的基础布局是示例，静态资源与路由需由宿主应用配置。平台字段和消息可见范围需针对实际环境另行验证。

与线上逻辑相关的公开化差异：

- 备注数据库默认使用当前目录下的示例文件名，可用 `FOLLOWUP_NOTES_DB` 显式配置；没有附带任何数据库或生产路径。
- 真实渠道授权工厂已替换为拒绝连接的占位接口；采用测试用的虚构授权工厂运行。关联草稿的账号和来源标记只从显式环境变量读取，默认不开启。
- 已删除两个只覆盖真实授权实现的测试；其余测试中的账号和数据均为虚构。测试通过并不验证真实渠道授权或线上配置。
- 数据来源与备注存储分属不同数据库。列表多次校验可以减少已知竞态，但跨库不是原子快照；恢复来源、状态或权限变化后应从第一页重新筛选。
- 不包含真实密码、密钥、用户账户、客户聊天、配置、生产数据库、服务器部署脚本或连接信息。

## 合成测试

需要 Python、SQLite JSON 支持，以及 `starlette`、`jinja2` 和与 Starlette 兼容的 `httpx`；测试仅使用临时目录：

```sh
python -m unittest -q test_followup_list test_followup_route test_conversation_notes test_owner_inbox
```

界面使用 `templates/v3/followups.html`、`followups.css` 和参考版 `unified_workbench.css`。页面上的相对 URL 是示例应用路由和静态资源引用，不是服务器地址。
