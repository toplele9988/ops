# 阿里国际站接收与草稿：脱敏参考候选

此目录分为两层，均不能直接替换生产服务：

1. `reference_snapshot/` 是从现有接收器与实时草稿器生成的**完整代码结构快照**。它保留原函数、类、查询和主要流程，将部署账户、局域网网段和服务文件路径替换为 `ICBU_EXAMPLE_*` 环境变量或示例值，禁用脚本直接启动。转写使用 Python AST，注释和原格式不保留；模型名单、公共平台 URL、协议字段和错误分类作为业务逻辑保留。`sanitization-manifest.json` 记录各替换所在原行、对应变量和快照校验值。快照不是可运行产品，不应直接 import 或部署。
2. `receiver.py` 和 `drafts.py` 是**从需求整理的最小演示**，不是生产源码的逐行等价替代。它们只使用标准库、独立 SQLite 和可注入的检索/模型接口。测试使用合成账号、合成消息和内存中的合成产品参数，不登录平台或访问外部服务。

匿名化的浏览器探针拆分模块及 Node 合成测试见 [`probe/`](probe/README.md)，缺少生产组装入口，不是可安装用户脚本。

## 精简演示的配置和边界

演示入口读取 `INBOUND_DB`（绝对路径，父目录需由当前用户拥有且权限为 0700）、`INBOUND_ACCOUNT`、`INBOUND_TOKEN`（至少 32 字符）、`INBOUND_ALLOWED_HOSTS`（逗号分隔），以及可选 `--port`。服务仅监听本机回环，不内置口令、真实账号、生产路径或公网开放配置。载荷要求显式填写 `history`、`role` 和稳定的 `message_id` 或 `event_id`；只有外部调用方注入验证器并确认实时证明，买家新消息才排队生成草稿。默认入口没有实时证明验证器，所有消息只归档；不会调用模型或对外发送。URL 只作来源，删除查询和片段，不发起网络请求。

这里没有对外开放的草稿查看/发送 API，也没有生产级凭据管理或 HTTPS 反向代理。演示数据库包含明文消息和草稿，须使用合成数据；目录和文件权限检查并不等于磁盘加密。处理中的进程异常退出后，本例不会自动恢复 processing 状态。若要生产化，必须另行实现可靠租约恢复、保留实际接收协议兼容、账号令牌映射、数据迁移和运维监控，并完成真实场景验收。

## 与现网的主要差异及缺失依赖

| 项目 | 脱敏快照 | 精简演示 |
|---|---|---|
| 实时身份和时间证据 | 原基线、水位、会话、角色、探针版本和时间窗逻辑作为源代码保留；账号和路径改为示例配置。 | 不实现现网证据验证；默认不排队，仅合成测试注入假验证器。 |
| 接收来源 | 保留来源验证、平台导入、探针下载/心跳、命令接口等原代码调用。 | 只有独立接收端点；额外必需稳定 ID 和显式角色/历史标记，可能不兼容旧探针。 |
| 数据库 | 保留现网表结构及租约、作业/检查点相关代码，但依赖外围模块；不是迁移脚本。 | 使用简化的新表结构，和生产数据库不兼容；不得指向原库。 |
| 检索与生成 | 保留现有知识检索和国内模型接线、预算与检查点控制调用。 | 使用注入函数，只有合成检索和草稿测试，不连接实际知识库或任何模型。 |
| 恢复与发送 | 原实现涉及状态恢复、失败处理及其他运维接口。 | 只记录成功/失败，无自动恢复、重试、发送或客户回填。 |

快照直接或间接依赖以下本目录未提供的项目模块：`icbu_official_imports`、`icbu_probe_download`、`icbu_probe_heartbeat`、`icbu_operations`、`icbu_knowledge_drafts`、`domestic_cli`、`domestic_digest`、`supplier_knowledge.icbu_quota_only_models_v1`、`video_knowledge.analysis_budget_policy`、`video_knowledge.assistant_models`；具体导入以 manifest 为准，补文件前也必须逐一审查脱敏及其传递依赖。它们涉及真实队列、知识检索、模型凭据和预算，不能因快照能编译就声称可运行。

## 检查

```sh
python3 -m unittest -v test_receiver test_snapshot
```

测试覆盖本地 HTTP 认证、合成消息幂等与并发、历史消息不升级实时、未通过证明不入草稿队列、合成检索与英文草稿、失败脱敏，以及快照语法、直接启动禁用、目录/局域网字面量和函数结构计数。快照未做完整依赖导入或真实执行；结构对照不等于完整行为测试。公开版本已按常见凭据与隐私模式扫描；实际使用前仍须检查许可证、配置与所有依赖。

12 项测试已在本机及目标服务器的临时隔离目录中通过，使用合成数据并清理临时目录。针对已知账号名称、私网地址、部署绝对路径和常见凭据赋值的定向正则扫描没有发现真实值；测试文件有一个合成用户信息格式和一个明确的合成测试令牌触发通用规则。这不替代专业密钥扫描或逐行隐私审查。
