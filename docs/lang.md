# 收到看中文，回复用英文和当地语言

打开会话后，对方发来的外文消息会自动翻成中文。中文、我方消息、空消息和只有符号的消息会跳过。
原文下方显示灰色小字译文；点击「只看中文」可隐藏原文文字，附件继续保留。
点击「看原文」恢复对照。浏览器会记住选择。

译文沿用原有持久缓存。刷新页面、重新打开会话、后台预翻译和人工翻译共用缓存。
已成功翻译且原文、目标语言、术语规则没变时，不再调用模型、不再扣额度。
会话列表最后一条消息已有完整中文缓存时，预览显示中文；没有缓存时继续显示原文。

每小时默认允许 120 次翻译调用。用完后显示「本小时翻译额度已用完，xx 分钟后继续」。
自动翻译以普通状态提示返回，保留已完成部分；页面到期后补齐未完成部分。
模型暂时不可用时不会连续重试，可人工点击「重试翻译」。

回复框下可以生成英文和当地语言稿。始终先出英文；客户母语已确认、不是英语且开关开启时，
再附当地语言。母语未知时先出英文，不再阻止起草。国家只作提示，不能据此认定母语。
两段各有回译核对稿，各自检查数字、型号、金额、链接和术语。新增事实标红；
保留片段丢失时拒绝采用。检查通过后才可点击「采用回复稿，填入回复框」。
发送正文是英文在上、当地语言在下，中间空一行。只有英文时不加第二段。
采用不会发送，原有人工确认流程继续保留。

「语言设置」新增默认开启的「收到的消息自动翻成中文」；原回复偏好改为
「回复同时附当地语言」，新库默认开启，已有明确选择继续保留。
关闭前一个开关后只读取现有缓存，不启动自动翻译；仍可对未完成消息手动翻译。
关闭后一个开关后起草只生成英文。「我的阅读语言」继续用于回译稿，自动收信固定译成中文。

## 接口

沿用 `/api/v1/lang` 现有路由、身份验证、发前复查和宿主表单校验。没有新增路由挂载要求。
表单仍须为 URL 编码，正文最多 8KB；不能传数据库路径或发送目标。

| 接口 | 本次变化 |
| --- | --- |
| GET、POST `/settings` | 增加 `auto_translate_incoming`；保存时为 `0` 或 `1`。`auto_native_send` 表示是否附当地语言 |
| POST `/translate` | 增加 `mode=auto`、`cached`、`preview`；不填时沿用 `manual` |
| POST `/compose` | 始终出英文，按设置附当地语言；返回每段译文、回译和检查结果 |

自动翻译表单：`conversation_key`、`mode=auto`。一次请求处理详情所用的最近 300 条消息，
后端筛出对方外文消息，再按现有规则分块。每块约 1800 字，每次模型最多八块。
单条消息上限 64000 字，超过会明确提示。可选 `message_indices` 保留每次最多 20 条的人工选择格式。
`mode=cached` 同样筛选，但只读缓存，不调用模型。

响应保留 `target_language` 和 `items`。每项继续包含 `index`、`source_hash`、`source_text`、
`source_characters`、`source_truncated`、`text`、`error`、`cached`、`complete`、`chunks`。
`source_text` 和哈希对应前 4000 字，与页面文字比对后才显示，防止消息序号变化时错配。
成功返回 `quota_exhausted=false`；自动翻译遇到额度不足返回 HTTP 200，并附
`quota_exhausted=true`、`retry_after`（秒）、`hint`，已完成部分仍在 `items`。
人工翻译、识别和起草仍沿用 HTTP 429、`Retry-After` 和中文额度提示。

列表预览表单：`mode=preview`、`conversation_keys`（会话键的 JSON 字符串数组，最多 40 个）。
返回 `previews`，每项含 `conversation_key`、`source_text`（列表原文）、`text`（中文预览）。
只读收件箱快照和翻译缓存，不拉取会话完整历史，不调用模型，也不写审计。
前端按表单长度继续拆批，并比对当前列表原文，避免显示过期预览。

起草表单仍为 `conversation_key`、`text`。响应新增：

- `english_text`、`local_text`（没有第二段时为 null）、`include_local`（生成时的开关值）。
- `versions`，按英文、当地语言排序。每项含 `language`、`text`、`back_translation`、`validation`、`back_validation`。
- 兼容字段 `text` 为两段空行拼接后的发送正文；`back_translation` 为回译稿拼接。
- 顶层 `validation`、`back_validation` 汇总各段检查；`warnings` 标明哪一段需要核对。
- 母语未确认或自动识别把握不足时，`native_language=null`。

两个版本分别与原稿核对，避免把双语中正常重复的型号、金额当成新增事实。
每段及回译有风险时显示红色提示，并禁用采用按钮。占位符缺失等结构错误不会交付可采用稿。
修改原稿、母语或回复偏好后，需要重新生成。

## 存储和模型

独立语言库默认路径和 `IMGW_LANG_DB` 配置不变；不改业务档案库。
沿用 `translation_cache` 的原文哈希、目标语言、术语表指纹联合键，成功块立刻入库。
术语变化后会使用新缓存；不安全的块不入库。缓存中保留译文，审计只记录字段名，不记录正文。

旧库首次写入时自动为 `settings` 增加 `auto_translate_incoming INTEGER NOT NULL DEFAULT 1`，
保留原有语言和回复偏好。新增 `pretranslate_schedule(id,next_at)`，只保存下次后台扫描时间。
写入和翻译操作继续使用原有跨进程锁。

默认模型仍走 `inbox.ai.official_runner`，使用独立余额和语言额度。
调用统一经过 `console.ai_gateway.run`；以服务账号运行时由公共入口直连网关。
验证模型返回来源，解析信封中的字符串 `answer`，去除代码围栏后读取 JSON。
翻译输出为 `{"blocks":[{"index":1,"text":"译文"}]}`；识别输出为语言和把握。
旧编号文字格式继续兼容，方便已有假模型和旧调用端过渡。
只提交本次翻译需要的文字，不附姓名字段、联系人资料或其他会话。

小时额度由 `IMGW_LANG_HOURLY_LIMIT` 或构造参数配置，默认 120。
识别、翻译、回译共用语言额度，缓存不占额度。一次模型入口内部最多尝试三次，
额度按入口调用计数；外层不会再自动套重试。测试全部使用假模型。

## 后台预翻译

`Lang.pretranslate(limit=20)` 在收件箱已有快照中选择最近 48 小时内收到的外文消息，
跳过我方、中文、空文本、未来时间、超长消息和已有完整缓存；每次最多翻 `limit` 条。
`limit` 为 1 至 300 的整数。返回尝试条数、完成条数以及可能的额度提示。
关闭收信自动翻译后，后台也不再调用模型。

`PretranslateSchedule(lang).poll()` 每五分钟最多运行一次，每次最多 20 条。
时间保存在语言库中，多个实例或进程共用节流；先预约时间再工作，重启后也不会密集补跑。
本模块不启动线程、不创建服务、不连接发送器。接线片段见 [本次交付说明](integration-translate.md)。

## 验收边界

开发演练只用虚构会话、临时数据库和假模型，没有真实模型调用、客户发送或部署。
文字规则不能可靠判断所有混合语言及中日共用汉字；联系人母语仍可人工确认和锁定。
保留片段检查不能证明整段语义准确，发出前仍需核对。
本快照缺少原有媒体模块；测试的临时依赖处理和完整结果见交付说明。
