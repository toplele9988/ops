# 产品逻辑与信息架构

参考对象：阿里国际站卖家后台、网易外贸通这类外贸 SaaS。它们共同的做法，是我们要学的：

1. **按业务对象和流程组织，不按技术功能组织。** 对象是 询盘/会话 → 客户 → 商品与供应商 → 报价 → 订单 → 物流与收款。菜单里看不到"采集""抽取"这种技术词。
2. **首页是工作台。** 一屏看完今天要做的事：待回复、待确认、待跟进，加上各渠道和数据的概况。点进去就是处理，不是看报表。
3. **客户是中心。** 一个客户的所有往来（询盘、聊天、报价、订单）能在一处按时间看到。
4. **前台与后台分开。** 前台是业务人员每天用的；后台是管账号、渠道、模型、知识库的。
5. **整屏利用。** 列表、详情、辅助信息并排（三栏），而不是一条窄列居中。
6. **不会用软件的人也能用。** 每页只做一件事；主按钮只有一个，名字说明会发生什么；空状态告诉你下一步；危险动作可撤销；任何发给外部的内容都先出草稿、人确认后才发。

## 导航

### 前台：业务

- **工作台**：待回复的买家、AI 已起草待你确认的回复、要催的供应商、渠道概况。
- **商机沟通**：收件箱。三栏：会话列表 / 对话 / 客户信息和 AI 建议回复。
- **客户**：按买家聚合，看最近联系、会话数、是否待回复。
- **产品与供应商**：供应商包装核对（影响运费和利润的第一环）。
- **报价与订单**：规划中。依赖包装资料和物流运价。
- **学习与改进**：AI 开发灵感库。

### 后台：系统

- **渠道接入**：每个渠道、每个阿里账号是否在线、最后收到消息的时间、有没有积压。
- **模型与任务**：模型额度、AI 任务运行情况。
- **知识库与采集**、**账号与权限**：规划中或跳转到原控制台。

## AI 在哪里干活

- **起草回复**：读取一个会话的历史，用买家的语言起草。只给草稿，不替你发送。凡是价格、库存、交期、运费、规格，草稿里写成【待确认：…】并列出需要你确认的事项，不允许编造。
- **整理与分类**：视频号卡片、供应商规格条目（已做）。
- **提醒**：把"买家说完话超过 N 小时没回"这类事放到工作台最上面。

## 不做的事

- 不自动发送任何客户消息。
- 不绕开阿里登录留在 Win10 的约束；回复通过人复制到阿里后台发送。
- 不把客户内容提交到公开仓库；测试一律虚构数据。
