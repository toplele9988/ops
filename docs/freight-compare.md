# 物流选择比价（I2 + R2-B）

本模块沿用 I2 的来源渠道、整票运费比较和选择记录。本轮修复换货代累加、线路边界及承诺期限，并接入报价页和价格建议页。未部署、未连接真实渠道或真实模型、未访问生产业务库，未 commit/push。全部验证只使用虚构单位、两目的国及临时 SQLite。

## 来源渠道

`freight_quotes.channel` 按运价记录保存，可选值：

| 值 | 含义 |
| --- | --- |
| `platform_alibaba` | 阿里国际站平台物流 |
| `forwarder` | 外部货代，默认值 |
| `other` | 其他来源 |

选择把来源放在运价记录而不是 `parties`：同一家往来单位可能同时给出平台物流和外部渠道价格，单独标记单位会把不同来源混在一起。来源也进入运价线路键，因此同一货代、目的地和服务可以同时保留两个渠道的当前运价。历史行通过 v9 的 `DEFAULT 'forwarder'` 迁移值保留既有含义。

档案录入继续使用 `POST /api/v1/archive/freight`，可带 `channel`，省略时为 `forwarder`。新增部分更新 `POST /api/v1/archive/freight/{id}/update`，字段沿用运价字段并可单独修改 `channel`。抽取员接受接口 `POST /api/v1/extract/suggestions/{id}/accept` 也接受同一字段；省略时使用 `forwarder`。档案回复中的运价 DTO 返回渠道值。价格建议页面现在明确选择平台/外部/其他来源，可人工保留 `transit_days_min` / `transit_days_max`，沿用已发布接受接口，无新增抽取字段或迁移。

## 报价轮选项

`GET /api/v1/quotes/{id}/freight-options` 使用该轮的产品行、采购数量和冻结包装字段，不改报价轮。可选 `mode=air|sea|express|rail|truck` 筛选；未筛选时返回各运输方式，因为报价轮尚无运输方式字段。

只返回每个线路/渠道当前 `confirmed` 记录中 `valid` 或 `expiring` 的运价。采用档案现有 `current_quote` 与 `quote_state` 规则；日期为未来、过期、无有效期、suggested/rejected 或被更新的同线路报价替代后，都不进候选。目的国已填写时精确匹配；未填写时列出全部目的国，设置 `destination_unspecified=true` 和提醒，只能查看，不能计入报价成本。推荐按目的国、目的地细分、运输方式、起运地和服务范围分组；不同范围不直接排成同类最低价。

每项包含运价 id、货代名称、线路、运输方式、计价单位、单价、最低收费、币种、时效、来源渠道、有效期状态及剩余天数。人民币运价会调用现有 `quotes.freight.calculate`，返回实重、体积重、计费重量、体积、计费基数及人民币总金额；最低收费使用原算法。包装缺失时仍展示选项，但 `calculable=false`、`amount_cny=null`，并按产品行给出缺少外箱长宽高、毛重、每箱数量或已确认采购数量等原因。非人民币运价会显示原币计算结果与币种，但不能换算成人民币、不能作为报价轮运费行选择，原因会明确标出。

推荐只作提示：

- `cheapest`：人民币总价最低；同价项目都标注。
- `fastest`：已填写时效范围的项目中，按最低天数、再按最高天数排序；并列都标注。
- `balanced`：可计算人民币金额且时效齐全、价格不高于最低价 110% 的候选中，按最快时效标注；并列都标注。

不满足对应计算条件的候选不会得到该标签。标签不会改写报价轮或代老板选择。

## 选择并记档

`POST /api/v1/quotes/{id}/freight-options/choose` 使用 URL 编码表单：

| 字段 | 规则 |
| --- | --- |
| `confirm` | 必须为 `1` |
| `freight_quote_id` | 必填，须仍为该报价轮当前目的国下可用的人民币运价 |
| `reason_type` | 可选：`cheapest`、`fastest`、`other`，默认 `other` |
| `reason` | 最多 200 字；页面要求人填具体原因，不根据推荐标签自动代填 |
| `selection_mode` | `replace` 替换方案，或 `append` 追加运输段；已有方案而未明确选择时阻断 |
| `replace_cost_id` | 替换时必填，只能是本轮同方式的自动运费，必须人工确认 |
| `segment` | 追加时必填，说明此费用覆盖哪段；每段仍按整票计算 |
| `request_key` | 替换/追加必填，8–80 位字母、数字或连字符；同一编号只能表示同一请求 |

替换在同一档案写事务中校验新报价、算价、插入新成本、移除指定旧成本、记协商与案子事件；任何一步失败都保留旧方案并回滚审计。替换不允许跨运输方式；不同路线或服务即使方式相同也必须由人核对范围后明确选择，系统不推断其相等。

追加只在明确运输段和原因后计入；金额会与其他段相加。同一运价不能被静默用于另一运输段，需先向货代核对范围并取得对应运价。重复选择同一已有运价保留兼容去重行为，但不同请求、不同段不能冒充追加成功。

同一 `request_key` 的完全相同请求重复提交返回 `reused=true`，不重复费用、协商、事件或审计；同编号内容改变返回 409。请求标记与金额计算留在现有记录中，不加档案字段/迁移。目标方案已在费用中时，替换也会留住新请求的操作记录，随后重放不再查已删除的旧行。普通原因、运输段和协商正文禁止写系统请求标记。

旧 `/quotes/{id}/costs` 自动运费入口也核对当前报价与目的国，已有自动方案时要求转到明确替换/追加；`recalc` 校验目的国后才能采用当前同线路报价。改本轮目的国会使不匹配的旧费用阻断发出，不能只改国家标签沿用旧价。人工运费同样须指定匹配目的国及运输方式；起运地或服务范围未明确时提示待核对。

客户有效期晚于产品成本、运费或任一人工费用有效期时阻断；需要向供应方取得延长期限后的报价或缩短客户承诺。本轮不实现人工锁价旁路。DDP 始终提示税费、清关及附加费须人工核对，界面只称已登记成本小计，不称全部到门成本已确认。

报价页展示 `amount_in_quote_currency` 和 `currency`。外币运价始终 `amount_cny=null`、不可选，不能使用原币数字冒充人民币；无换汇与汇率推断。

## 货代运价比价视图

`GET /api/v1/freight/compare?destination_country=&mode=` 独立于报价轮；目的国和方式都是可选精确筛选。返回各货代当前有效或即将到期的报价及单价、计价单位、最低收费、时效、有效期、剩余天数和渠道。缺省每页 30 条，支持 `page`、`page_size`（最多 100）。不含过期、无有效期或被更新取代的报价。

## 安全、迁移与挂载

路由放在 `v3_quotes_api.py`，沿用报价 API 的认证、principal、POST 前 recheck、GET 返回前 recheck、表单限制、固定中文错误和响应头；CSRF 仍由宿主中间件验证，`csrf` 字段不会写入业务记录。演练脚本已通过既有动态模块列表挂载 `v3_quotes_api`，无需增加第二条挂载路径。

I2 已发布的 v9 保持原样；本轮不加档案迁移、不改已发布迁移。GET 不主动迁移旧数据库，读旧结构时渠道按 `forwarder` 兼容展示。新增条款/单据状态使用独立配置库，见 [报价文档](quotes.md)。

比价计算和接口测试使用固定日期、临时 SQLite、虚构货代与价格，不访问网络或生产库。`freight_compare` 路由由 `v3_quotes_api.build` 创建；已存在的演练服务器动态挂载列表包含该模块。

本轮测试、源码基线与部署/回滚步骤见 [R2-B 交付记录](r2b-delivery.md)。没有运行真实库演练、固定端口服务或全页面冒烟；页面仍待总指挥统一验收。
