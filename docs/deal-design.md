# 一笔生意（案子）：贸易商的核心对象

## 为什么要改

之前的系统以"渠道里的消息"为中心：收件箱里一个个会话。但贸易商的工作单位是**一笔生意**：同一时间，你和客户谈需求，和产品供应商核实尺寸重量价格，和货代要运费，有特殊要求还要拉配套供应商（打样、包装、认证、验货、报关），几方来回拉扯、讨价还价，直到客户付款才算成交；成交后还有备货、验货、发货、签收、售后，以及返单和意见反馈。

这些消息分散在阿里、WhatsApp、微信的不同会话里。如果系统不知道"哪几个会话属于同一笔生意"，就无法回答最重要的问题：**这笔生意现在卡在谁手上？下一步该做什么？赚不赚钱？**

所以核心对象是 **案子（Deal）**，渠道只是把消息送进来的管道。

## 往来单位（Party）

所有和你打交道的对象统一管理，一个单位可以有多个渠道身份：

| 类型 | 是谁 |
|---|---|
| customer 客户 | 买家（阿里买家、WhatsApp 客户、微信客户群） |
| supplier 产品供应商 | 工厂、档口 |
| forwarder 货代 | 物流供应商 |
| vendor 配套供应商 | 打样、包装、认证、验货、报关等 |

**渠道身份（Identity）**：一个会话或联系人属于哪个往来单位。同一个客户在阿里和 WhatsApp 上是同一个人，系统要能把两条会话挂在同一个客户名下。新增渠道只需要适配器把消息送进来，再把会话关联到往来单位，其余全部复用。

## 案子的流程

状态（open 进行中 / won 已成交 / lost 已丢单 / paused 暂停）与阶段分开。**成交的定义是客户付款**，所以"已成交"在收到付款时才设置。

| 阶段 | 做什么 | 默认待办（系统自动生成，可改） |
|---|---|---|
| 1 询盘 | 客户提出需求 | 弄清要什么产品、数量、目的国、价格预期 |
| 2 询价核实 | 向供应商和货代确认 | 向供应商确认型号、尺寸、重量、价格、交期；向货代要运价；有特殊要求时找配套供应商 |
| 3 报价 | 算价格并发给客户 | 核对成本有效期；算到手价并检查倒挂；发报价 |
| 4 谈判 | 讨价还价 | 记录客户还价；回供应商和货代协商；更新报价轮 |
| 5 待付款 | 客户确认，等付款 | 发 PI；确认付款条件；收款确认 |
| 6 已成交·备货 | 客户已付款 | 下单给供应商；确认交期；通知客户生产进度 |
| 7 验货 | 出货前检查 | 安排验货；确认外箱、唛头、数量 |
| 8 已发货 | 货交货代 | 订舱；发提单和发票给客户；确认预计到达 |
| 9 已签收 | 客户收到货 | 确认签收；跟进使用反馈 |
| 10 售后 | 问题处理 | 记录问题；问题转给供应商或货代；跟进解决 |
| 11 返单 | 复购 | 询问复购；对照上次的价格和反馈 |

## 参与方与"卡在谁手上"

一个案子有多个参与方（客户、供应商、货代、配套供应商）。每个参与方关联一个或多个会话（可跨渠道）。系统根据**每个会话最后一条消息是谁发的**自动判断：

- 最后一条是对方发的 → 球在我们手上（要回复）；
- 最后一条是我们发的 → 在等对方；
- 超过设定时间没有回应 → 提醒催一下。

案子列表因此能直接显示"在等客户 / 在等供应商 / 在等货代 / 要我处理"。

## 报价轮与成本

每次报价是一个"报价轮"，保存当时用的成本和价格：产品成本（引用供应商报价）、运费（引用货代运价）、配套费用、利润。**引用的报价如果过期或没写有效期，系统拒绝用它报价**，并提示去要新价。同时检查价格倒挂。每轮可以记录客户还价和我方回应，所以可以回看谈判过程。

## 问题与反馈

售后问题和客户意见是案子上的"问题"：记录内容、涉及哪个产品、哪一方的责任；一键起草转给供应商或货代；解决后关闭。按产品和供应商汇总，用来改进产品、挑选供应商。

## AI 在哪里帮忙

| 岗位 | 做什么 | 依据 |
|---|---|---|
| 案子秘书 | 读该案子所有会话，写"进展摘要 + 每一方在等什么 + 建议的下一步" | 全部关联会话、待办、报价轮 |
| 分拣员 | 新消息进来，判断它属于哪个案子、哪个往来单位 | 往来单位、案子、产品库 |
| 分角色起草 | 同一个案子里，对客户写销售回复，对供应商写核实尺寸重量价格的询问，对货代写要运价的询问 | 知识中枢 + 案子里的已确认事实 |
| 核价员 | 从已确认的产品和有效运价算到手价，检查倒挂 | 档案、货代运价 |
| 巡检员 | 报价快到期、对方久未回复、待付款久未到账、物流节点 | 案子与待办 |
| 反馈归集员 | 汇总意见和问题，按产品和供应商分类 | 问题记录 |

## 分阶段做

1. **A 地基（这次）**：往来单位扩展与渠道身份、案子、参与方、会话关联、待办、时间线、阶段模板、"卡在谁手上"，以及案子看板和案子页；收件箱里可以把会话关联到案子或新建案子。
2. **B 报价轮与核价**：成本构成、有效期检查、倒挂检查、还价记录、生成报价单与 PI。
3. **C AI 岗位**：案子秘书、分拣员、分角色起草。
4. **D 履约与售后**：下单、验货、发货节点、问题与反馈、返单。
5. **E 报表与团队**：利润、转化、供应商表现；多账号分工。

## 验收场景（用你自己的真实案例）

拿一笔真实生意（例如收件箱里"4 个灯架、USD 56.50、运费 USD 15.62"那一笔）完整走一遍：建案子 → 关联客户会话和供应商群 → 看到卡在谁手上 → 记录待办 → 推进阶段。每个阶段做完后，由你来说"这样对不对"，我再改。
