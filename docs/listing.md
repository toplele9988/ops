# 发品草稿（第一阶段）

本阶段生成可供老板审核的商品内容草稿，允许人工修改、标记“可以发”、导出和记录人工发布结果。系统不登录阿里国际站、不自动填表、不自动发布，也不向渠道发送内容。

## 数据与迁移

实现前检查了 `src/console/archive/`，最高版本是 v9；新增 `migration_v10.py` 和 `schema_migrations` v10，不改已有迁移。若合并时其他任务也占用了 v10，合并前须协调版本号并保留单一顺序。

`listing_drafts` 挂在档案 `products` 上。每个产品、渠道可生成多个版本，旧版本不覆盖。记录包括渠道、状态、对外字段、中文核对稿、合规结果、来源 ID、输入指纹、创建/审核人和时间、人工填写的发布链接/ID。另有两个仅内部读取的字段：`generation_source`（`ai`/`rules`）和 `internal_pricing_json`（成本依据、汇率和利润率说明）。成本金额不会放入对外字段或导出。

listing 使用 `role_runs` 的 `listing` 岗位和 `product` subject，出现在 `/api/v1/roles` 与 `/api/v1/roles/runs`。v10 扩展了 `role_runs` 的检查约束并保留既有行，同时给 `role_ai_reservations` 增加 `bucket`；listing 的桶独立计数，缺省最多每分钟 12 次、每小时 12 次 runner 调用。每次调用按 `official_runner` 最多三次网关尝试预留额度（失败尝试也计入），所以同时限制潜在网关调用量；超额或模型失败仍保存规则草稿，并记录 `source=rules`。

## 草稿事实与价格

起草只从已确认且未合并的产品读取名称、型号、分类、功率、产品尺寸、外箱三边、毛重/净重和每箱数量。有效的当前已确认 offer 可补充 MOQ、计价单位和交期。档案的自由描述、供应商备注、产品来源正文和成本金额不进入提示词。提示词会取有限的知识检索片段，但只保留 `technical` 资料族中明确标为“公开技术参考”、且无保密/成本标记的片段；来源只以 ID 保存，不复制正文。已知供应商/客户名称只在内存中用于防泄漏筛查，不写入草稿或提示词。

外发文案按英文生成，另存给老板看的中文核对稿。未知属性使用 `To be confirmed: …` /“待补充”。AI 使用现有 `official_runner` 的纯文本约定，不要求 JSON；解析失败、超时、额度已满或输出中出现已知内部内容时，改用仅含白名单事实的规则半成品。系统不把模型错误原文或提示词写入运行记录。

价格使用当前有效的已确认成本 offer、`quotes.calc`、`quotes.fx` 的本地 USD/CNY 缓存和目标利润率。默认目标利润率为 15%，可在生成时以 0–90 的百分数覆盖。只有一个有效报价且缺少批量成本断点时，仅建议已确认 MOQ 的一档，不推演数量折扣。目标市场匹配到唯一当前有效、人民币计价且按 kg/cbm 计价的运价时，可把运费并入建议；没有匹配、多个路线歧义、包装不全、成本/MOQ/单位/汇率缺失时不猜价，`price_tiers` 留空并在内部审核视图说明原因。对外阶梯价默认为 USD。

`GET /api/v1/listing/drafts/{id}` 是内部审核视图，会含成本计算依据和来源 ID；`GET .../export?format=text|csv` 只输出阿里字段顺序的对外内容，不含内部价格依据、来源引用、合规报告或中文核对稿。人工修改后重新计算合规并将状态退回 `draft`；审计表只记录字段名，不记修改值。

## 合规与审核

合规检查是可扩展的纯函数：标题长度 1–128、关键词 3–5 个、夸大/绝对化用语、可配置商标词表、未补齐属性，以及图片数量/分辨率提示。默认商标词表为空，可向 `Listing(..., brand_terms=(...))` 注入老板维护的词项。违规仍可保存为草稿；任何阻断级问题都会拒绝标记 `ready`。缺属性是警告，图片检查只提示，图片不在此阶段处理。

图片登记现状已经核对：`company_media` 是消息附件索引，没有产品归属或公开商品图标志，不能安全地自动选作商品图片。新草稿的 `image_refs` 因此为空；人工引用也必须由宿主注入 `media_lookup(product_id, ref)` 确认它是绑定该产品的公开图片。未配置该检查器时，非空图片引用会被拒绝。

状态流转：

| 当前状态 | 操作 | 结果 |
| --- | --- | --- |
| `draft` | `ready` | 无阻断问题时记下审核人/时间 |
| `ready` | `draft` | 撤回审核；字段修改也会自动回到此状态 |
| `ready` | `published` | 必须 `confirm=1`，并人工填写 `published_ref` |
| 任一未发布状态 | `archived` | 保留版本并归档 |
| `published` | `archived` | 保留发布链接/ID并归档 |

本阶段没有触发发布的接口，也没有自动填表代码。

## 接口

- `GET /api/v1/listing/drafts?product_id=&channel=&status=&page=&page_size=`：分页列表。
- `GET /api/v1/listing/drafts/{id}`：内部审核详情。
- `POST /api/v1/listing/drafts/generate`：必填 `product_id`、`channel=alibaba|website`；可选 `tone`、`target_market`、`target_margin`。
- `POST /api/v1/listing/drafts/{id}/update`：仅接受标题、关键词、分类提示、属性、MOQ、单位、对外价格阶梯、交期、包装、卖点、描述、图片引用、中文核对稿白名单字段。JSON 字段通过表单中的 JSON 文本提交。
- `POST /api/v1/listing/drafts/{id}/status`：`status=draft|ready|published|archived`；published 还需 `confirm=1` 与 `published_ref`。
- `GET /api/v1/listing/drafts/{id}/export?format=text|csv`：只导出对外字段。
- `GET /api/v1/listing/products-ready?page=&page_size=`：列出候选/确认产品及缺失项，包括功率、外箱尺寸、毛重、每箱数量、有效成本报价和报价 MOQ。

路由沿用现有 principal/session 授权、宿主 CSRF 检查、写前 recheck、读后 recheck、统一 JSON 安全响应和固定错误文案。没有新增 web 页面。

描述字段单独放宽为最多 65,536 个字符；其余字段仍逐项白名单和长度检查。URL 编码后中文会膨胀，因此整个表单上限为 1 MiB，字段数最多 32。说明字段的放宽不扩大其它字段限制。

## 第二阶段：Win10 自动填表需要的准备

登录和浏览器会话继续只留在 Win10。221 不保存阿里 Cookie、密码或浏览器配置，也不直接连接阿里页面。后续需要在 Win10 执行器中新增受控的“填入草稿”能力：

1. 用独立命令/队列接收草稿 ID、渠道、`input_fingerprint` 和经审核的字段快照；通过现有安全通道认证，并限制到已登记的阿里账号/子账号。
2. Win10 浏览器读取阿里发品页面版本/字段标签，逐项填标题、关键词、类目、属性、MOQ、售价、交期、包装、描述及图片；遇到字段变化、必填缺失或校验不符时停止并回传原因。
3. 执行器须幂等：以草稿 ID + 指纹避免重复填写，回传运行 ID、账号、时间、页面结果和阿里商品链接/ID；保留可审计失败记录。
4. 由老板先在系统里审核 `ready`，Win10 只填表或保存平台草稿。发布按钮仍由老板在阿里浏览器里亲自点击；第二阶段也不能仅凭队列自动发布。
5. 用专门测试账号/非公开测试商品验收选择器、字段映射、断网恢复、重复任务、部分失败和页面改版；不得用客户消息做测试。

现有 `icbu_operations.py` 只有会话回复能力，没有发品动作。第二阶段需要新命令与页面适配器，不改写现有 `fill/send` 会话操作；当前草稿字段和指纹为该适配预留。

## 测试与边界

`tests/listing/` 全部使用虚构档案、fake Hub、fake AI 和虚构汇率，不访问网络、不调用真实模型。自动测试不能证明平台类目/属性映射或英文营销效果正确；老板仍须逐字段核对。此代码未部署，未更改 `/opt/imgw`、生产数据、`web/`，未发布或发送任何内容。
