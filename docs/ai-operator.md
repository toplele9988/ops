# AI 运营员

运营员收到新消息后，先看是谁、相关案子、当前阶段、最近往来和有来源的档案，再准备回复、问价、运费、报价、PI、订单和履约待办。当前交付已通过虚构数据验收，宿主挂载和真实演练步骤见 [INTEGRATION.md](../INTEGRATION.md)。

## 开关怎么用

首次全部关闭，处于演练模式：只保存草稿和决策，不联系任何人。自动执行必须同时满足总开关开启、退出演练，以及“动作等级、往来单位类型、单个联系人”三个许可。

| 等级 | 可以做什么 |
|---|---|
| 1 | 给产品/配套供应商问资料、价格、交期；向货代问运费，不下单、不确认付款 |
| 2 | 给客户回复已核实资料和常规跟进；按总纲，连续两周基本无需改稿后再开 |
| 3 | 报价、PI、订单、发货和案子操作；默认待你逐项确认，稳定后可逐联系人授权 |
| 永远人工 | 确认收款，只能到原案子页操作 |

“AI 待你确认”可查看原稿、删除不需要的事实段、确认或填写理由拒绝。新增数字、规格、交期或承诺要先补入已核准档案，再重新起草。已经发送了部分段落的动作不能修改余下正文。阿里没有可用发送通道，确认也不会外发，保留正文供原账号人工处理。

“一键全停”停止后续发送与执行，清除未发动作的旧人工授权。重新开启不会释放历史演练草稿；这些草稿仍须逐条确认。已进入渠道的一次请求无法撤回，需查看最终结果。

## 一条询盘怎样推进

1. 有明确客户、案子、产品和供应方关联时，同时准备供应商询价、货代问运费和客户回复，各自推进。未归属/多个案子有歧义时请老板确认，不猜收件人。
2. 供应商/货代回复经现有提取核对流程归档后，事件重新检查成本和物流依赖。未报价、无有效期、过期都先追问；不会用旧价顶上。
3. 成本、包装、线路、汇率与定价规则齐备后，复用已有报价计算器，保存成本和利润快照，给客户的正文只有销售报价。发送前再次检查有效期和版本。
4. 客户认可时准备 PI 和订单草稿；公司开票资料、付款/交付条款未确认时阻断。收款由老板在案子页核对，之后可安排验货、订舱、在途待办；不把待办当作已经发货。

运营员记录的资料变更是带消息来源的“待核对备注”，不会静默修改正式规格、价格或客户资料。待办到期和最后一条我方消息超过 48 小时未获回复，也会产生相应动作。

## 发送节奏与防错

按对方 IANA 时区，仅在当地 08:00–20:00 自动发送；夜间仍准备草稿，排到早上。默认每联系人 6 段/小时、20 段/天、至少间隔 30 秒，可在页面调整。计数包括失败和结果未知的尝试，不能靠重开页面绕过。

同一内容不会重复发送。每段发送前先留下持久记录；超时、崩溃或结果不明标为 unknown，不自动重试，也没有重发按钮。应先到原渠道核对，保留原记录。模型请求同样先记录事件，再调用；未知结果不会通过重放事件再调用。

客户回复的检索不含成本、保密资料和其他买家信息。模型只能选择已核准事实编号，不能自由编写数值或承诺。每条自动动作留存触发、上下文与来源、模型、输出、策略和发送结果；决策记录是内部资料，不能复制整个记录给客户。

日常模型只走 `ai-task run bailian_free --model auto`；复杂分析可显式使用免费池支持的 DeepSeek 候选，遵守统一入口的准入/未知停止规则，不新增密钥、不自动转付费。

## 当前边界

- 已实现中、英、西、法、葡的常规消息和报价模板；产品事实按已有核准语言输出。其他语言、缺失语言或时区会留待核对，不擅自用英语替代。PI/订单默认中英文，其他语言需注入已核准单据。
- 自动算价支持 EXW 与单一明确线路的 DDP；其他术语、额外费用或线路有歧义时交现有报价页。没有老板核准的定价规则就不出数字。
- 真实渠道发送依赖总指挥配置现有客户端、原账号绑定和渠道许可。开发验收使用假桥；页面显示 fake 时，“已发送”表示模拟调用完成。
- 供应商自由文本不会直接变成已确认成本。现有档案提取/核对与运营员事件必须由宿主连接；界面和作业挂载没有在本任务中修改共享文件。
