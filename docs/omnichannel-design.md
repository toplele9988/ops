# 全渠道沟通：设计（2026-10-30）

目标：阿里国际站、WhatsApp、微信（以后还有独立站）的客户沟通，在**同一个后台**里收、看、回、跟进；普通办公人员不需要知道背后是哪套技术。

学习对象：网易外贸通把 WhatsApp 通过浏览器插件接进来，客户消息进同一个客户档案；阿里国际站后台把询盘、客户、订单放在一条线上。我们的做法是同一个思路，但每个渠道按它真实能做到的程度来接，不假装。

## 1. 每个渠道现在真实能做到什么（2026-10-29 实测）

| 渠道 | 收 | 发 | 登录方式 | 现状与硬约束 |
|---|---|---|---|---|
| 阿里国际站 | Win10 浏览器里的油猴脚本把消息推到 221 | 经 Win10 执行器在已登录页面代发（代码已有，**从未验收**） | **登录必须留在 Win10**，不迁到 221，不导出 Cookie，不开调试端口 | 只有 Amy 1 个账号有数据（你有 6 个）；最近入库在 10/29 09:36 UTC，探针心跳停在 10/25 |
| WhatsApp | WAHA（WEBJS）会话 WORKING，109 个聊天，通过桥接入库 | 桥接网关已就绪：要显式确认发送人、幂等键防重发、收件人必须"发过消息"或被你明确确认、默认不自动发 | 手机扫码配对（页面已有） | 99 个聊天超过 30 天没动，近一个月活跃的只有约 9 个，所以入库只有 3 条是真实情况 |
| 微信 | 第三方 WTAPI 回调，每天上千条，28 个群（客户 3、供应商 17） | WTAPI 有回发链路，但属于对外发送，**单独授权后再做** | 第三方接口已登录 | 群名、成员昵称不完整 |
| 独立站（预留） | 网站聊天组件 → webhook | 同通道回复 | 站内访客，无需登录 | 接口先约定好，不做实现 |

**关于"把阿里采集改到现有系统"：** 阿里的登录和采集必须留在你 Win10 的浏览器里，这既是安全约束，也是外贸通的做法（它也是浏览器插件，运行在你自己的浏览器里）。能改、也应该改的是：**接收、存储、显示、回复调度全部在后台**，并把 Win10 那一端做成"有心跳、能自检"。采集停了，后台要第一时间告诉你"阿里已经 13 小时没收到消息，请检查 Win10 浏览器"，而不是安静地显示旧数据。

## 2. 统一模型

所有渠道都实现同一个接口（渠道适配器），后台只认这个接口：

```
会话 Conversation: key, channel, account, counterpart{id,name,country,role}, last{role,text,at}, waiting_reply, n_messages
消息 Message:      role(buyer|seller|internal), text, sent_at, attachments[], delivery(sent|failed|unknown|null)
适配器 Adapter:    list_conversations(), get_messages(key), health(), send(key, text, …)  # send 可选
```

`channel` 取值：`alibaba` `whatsapp` `wechat` `website`（预留）。新增渠道只写一个适配器，页面不用改。

## 3. 发送：草稿 → 你确认 → 发出

所有对外发送都走同一条流水线，而且只有你点了"发送"才会发：

1. **草稿**：AI 或你自己写。AI 草稿里的价格、交期、运费不确定的地方标成【待确认】。
2. **确认**：页面显示"发给谁、从哪个渠道、发什么"，你点"确认发送"。含【待确认】的草稿不允许发出，必须先改掉。
3. **发送**：带幂等键。状态只有：`发送中 → 已发出 / 失败 / 结果不确定`。**结果不确定的不自动重发**，由你去渠道里核对后手动处理。
4. **记录**：谁、什么时候、发给谁、发了什么、结果是什么，全部留痕，可查。
5. **总开关**：每个渠道一个"允许从后台发送"开关，默认关；WhatsApp 开关由你在后台打开。
6. **不做的事**：不自动群发，不发测试消息，不在没有你点击的情况下发送任何内容。

各渠道的发送方式：

- WhatsApp：走现有桥接网关 `/api/sendText`，actor 固定为"你本人（owner_explicit）"。第一次给某位联系人发之前，页面要你多确认一次（对应网关的"绑定收件人"）。
- 阿里：创建一个"代发任务"交给 Win10 执行器，在你已登录的页面里发出。**这条链路没验收过**，所以第一版默认只提供"复制草稿，去阿里发送"，代发任务在你亲自试过一次之后才打开。
- 微信：第二阶段。要先和你确认发送人身份、允许发送的群、以及防误发规则。

## 4. 渠道健康：采集停了要说出来

每个渠道、每个账号显示：最近一条消息的时间、24 小时条数、状态（正常 / 较安静 / 很久没有消息）。阿里额外显示 Win10 探针心跳，并给出"怎么检查"的几步：

1. Win10 上 Chrome 是否开着、是否登录了阿里国际站；
2. Tampermonkey 里"乐初探针"脚本是否启用；
3. 阿里页面是否停在"消息"页（脚本只在该页面采集）；
4. 电脑有没有休眠。

状态异常时，工作台顶部给出提醒，而不是藏在系统后台里。

## 6. 分阶段

- **阶段 A（本次）**：统一收件箱接入阿里 + 微信 + WhatsApp 三个渠道的收；渠道健康与阿里自检；独立站适配器接口约定。
- **阶段 B（本次）**：WhatsApp 后台直接发送（确认流程 + 记录 + 防重发）；阿里与微信先"复制草稿"。
- **阶段 C**：阿里代发任务验收、微信发送（需要你单独授权）；客户档案合并同一买家在不同渠道的会话。
- **阶段 D**：独立站接入、报价与订单。

## 7. 验收口径

不以"接口通了"算数。每个渠道的验收是：你在后台里看到的最新一条消息，和你在原渠道里看到的一致；WhatsApp 发送由你自己发一条给自己的另一个号码验证，系统不替你向任何客户发测试消息。
