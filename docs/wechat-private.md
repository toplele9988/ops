# 微信业务私聊入库

需求依据：老板 2026-11-03 确认「存私聊」，以及本次任务的实时、角色、回放、运营台与知识读取要求。状态：源码候选、隔离测试和部署回滚包已交付；未部署，未回放生产库。

部署与验收见 [INTEGRATION.md](../deploy/wechat-private/INTEGRATION.md)。生产入口、解析器、客户端、配置结构、数据库表结构及服务商本地文档均已只读核对。生产文件保持原样；工作区只改本任务指定文件。

外部私聊归一化后进入既有 `messages` 和 `message_scopes`，额外记录账号/对方、inbound/outbound 方向、五类业务角色及逐回调幂等回执。附件复用群媒体的下载、原件归档、文本提取和笔记子附件处理；消息本身使用终态，不进入回复或指令队列。内部指令联系人沿用既有工作入口。

现有运营台通过两个来源读消息：共享 `WechatAdapter`，以及 `console.ops_queue.inbox.wechat` 的本地投影。本包同时补齐两条路径。客户与供应商页的 `Parties.read` 通过同一 inbox 和已确认身份映射取得私聊时间线；名称识别不自动建立单位关系。unknown 对象直接列入「待你确认归属」。

角色先取既有身份/往来单位精确映射，再使用现有命名规则；不能判断时为 unknown。forwarder、vendor 在旧收件箱筛选中归 supplier，但完整业务类型保留。历史回放不会把内部指令当客户消息，也不会调用发送或模型。

实际知识入口 `console.kb.search.Search.search` 加入本地私聊关键词检索，含 ready 附件正文。owner 可读全部，product_facts 仅可读供应侧；customer_reply 不使用任何本次新增私聊命中，因此不会把其他客户或供应商的私聊带入客户回复。该补充是本地读取，不代表私聊已完成向量索引、结构化产品/报价建档或自动提炼。

已查本地 WTAPI 接口目录、正文与客户端，没有找到普通微信好友聊天的历史拉取协议；视频号私信同步接口不适用。因此只提供已保留回调的幂等回放命令，不创建虚构的补拉接口。服务商未推送或本地未保留的历史不能据此恢复。

隔离测试使用虚构消息、单位、票据、媒体与临时 SQLite，禁止网络和生产数据库访问。部署脚本核验生产 SHA、备份、停服务、原子替换、主动迁移、恢复运行；回滚保留新增数据与既有发送状态。全站 smoke 包含生产目录写入，本次只读交付未运行；部署前必须在授权环境通过项目要求的该项验收。
