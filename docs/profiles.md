# 会话画像

老板能看到对方是谁、做什么、问过什么产品、买卖走到哪一步。每条判断附原话和消息序号。没有读完就显示已读数量，不冒充全读完。

微信和阿里读取现有本地历史。WhatsApp 分页读取已有消息，只发读取请求，不下载附件、不登记附件、不发消息。分页使用 `offset`，每次前移 100，直到返回空页；短页后仍继续读。做法依据 [WhatsApp 桥接服务官方说明](https://waha.devlike.pro/docs/how-to/chats/#get-messages)。上游不支持分页时会报读取失败，保留旧画像。

图片显示为 `[图片]`，文件显示为 `[文件 名称]`。这次不识图、不识别文件正文。消息按时间排序，同一时间保留来源顺序，序号从 1 开始。大段文字拆开后保留原消息序号，全部片段读完才算读完这一条。

每窗约 6000 字，含日期、发送人、方向和原始时间戳。每个会话每次最多 30 窗，最新、最早交替处理，再逐次补齐中间。模型返回的原话必须出现在指向的消息里，日期也必须一致。原话最多 80 字。坏答案和超时不覆盖原有画像。

每次新消息累计到 30 条，或离上次读取超过 7 天，处理新窗口并重做汇总。旧窗口不重复调用。待补齐窗口会继续处理；新增不足 30 条时更新消息总数并标记尚未读完。发现历史删改或插入旧消息，会重建窗口，避免序号错位。

窗口过多时分层汇总。中间结果缓存到侧库，预算用完后下次继续。汇总必须复用已核验的证据，保留成交和售后证据。客户阶段由证据计算：我方报价后为已报价；已下单、付款或发货的任一证据可认定成交；成交后有售后证据才标售后。潜在或已报价但 90 天没有任何往来，标为沉睡。供应商发来的报价不当成我方给客户的报价。

明显系统通知、公众号类会话，以及没有业务词的家庭或私人群，先由规则判断，不调用模型。这类画像状态为 `skipped`，其余状态为 `ready`、`partial` 或 `failed`。未知内容不猜，缺项为空。

模型只走现有网关，免费池固定 `--model auto`。校验提供方、路由和实际模型；严格解析信封里的字符串 `answer`，先去掉代码块。每天默认最多预留 100 万词元，按 UTC 日计账。每次调用前按提示词字节数加 8000 输出余量预留；成功有用量就记实数，无用量、失败、进程中断保留预留值。真实运行有跨进程锁。只读演练的账本在内存，不占用或修改真实账本。

## 运行

```bash
env PYTHONPATH=src:/opt/imgw/wechat PYTHONDONTWRITEBYTECODE=1 \
  /opt/imgw/venv/bin/python -m console.profiles run --once \
  --max-conversations 20 --max-windows 30 --daily-budget-tokens 1000000
```

可加 `--channel wechat|alibaba|whatsapp`，也可用 `--only KEY` 限定会话。多个会话重复传 `--only`。`--max-windows` 是每个会话的上限。未到更新条件的会话不占 20 个名额。旧画像先处理，避免一直重复扫描最近的会话。

演练必须同时传 `--dry-run --report 目录`。报告放仓库外，或任务指定且已忽略的 `/srv/imgw-dev/ops/private_out/profiles`。侧库只读备份到内存；侧库不存在时不创建目录、数据库或锁文件。报告只保存数字摘要和画像，包括画像本身的证据；不包含窗口原文、提示词、模型原始答案或错误正文。报告目录可写性会在模型调用前检查。标准输出只含数字。

只读演练会调用真实模型，所以由总指挥在宿主运行。完整的 8 会话选样命令见 [交付说明](integration-profiles.md)。

## 查询约定

侧库固定 `/var/lib/imgw/ops-app/profiles/profiles.sqlite3`。读接口不会建库或迁移。

- `GET /api/v1/profiles?kind=&stage=&channel=&q=` 返回 `{items, counts:{kind,stage}, updated_at}`。计数及更新时间取全库，筛选只影响 `items`。搜索标题、公司、摘要、产品和人员。
- `GET /api/v1/profiles/{conversation_key}` 返回单个画像。没有记录返回 404。

两者都沿用运营台登录与登录复核。仅支持读取。画像字段与任务书完全同名，`people_json`、`products_json`、`evidence_json` 输出为数组，其余字段原样输出。`country` 是 ISO 两位码，`country_name` 中文，`language` 为 BCP47。摘要中文不超过 200 字。

分拣只采用 `ready/partial` 且把握达到 0.7 的画像。供应商档案匹配仍先用，保留 0.95/0.9 优先级。客户建议建客户案子或关联已有案子；供应商、货代、配套建议确认往来单位；同行、行业群、私人、系统及内部会话建议忽略。理由包含“AI 读了 N 条消息：摘要”。仍由人确认，不会自动改会话身份或建案子。
