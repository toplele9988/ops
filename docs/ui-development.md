# 工作台界面开发记录

## 已应用的检查方法

根据视频中介绍的网站设计方法，参考 [Hallmark](https://github.com/Nutlope/hallmark) 的界面检查思路，优先检查可读性、键盘焦点、响应式布局、减少动态效果以及真实状态。这里借鉴的是检查方法：项目并未安装或运行该工具，也未引入其素材或代码。

当前公开的工作台样式包含窄屏布局断点、焦点样式和 `prefers-reduced-motion`；账号页面提供窄屏布局与表单反馈。会话页面区分已归档、不可用和尚未接入等状态，避免把占位按钮表现为可用功能。跟进备注的 HTTP 测试覆盖保存和并发冲突；账号测试使用临时账户及数据库。

## 后续验收

- 用真实业务接口分别核验成功、失败、加载和空状态；发送是否成功以渠道回执为准。
- 在手机、平板、桌面与键盘操作下检查布局、焦点和表单错误；对比度与减少动态效果需在实际浏览器验证。
- 使用虚构数据构建订单、客户、供应商和设置的交互原型，再连接实际数据；不得把原型画面视为功能完成。
- 如采用其他组件或动画库，先核对许可、依赖、加载性能和是否向外部传输数据，再决定是否引入。

公开仓库目前包含脱敏页面候选与测试，不是完整生产前端。测试和部署状态见项目 README。

## 全局总览（2026-11-02，前端候选，未部署）

- 运营台首项「总览」现使用首页路由 `/`（应用挂载后为 `/app/`），原 `/overview` 保留同页别名。渠道、预算与覆盖区域读取 `GET /api/v1/overview`；UX 收口后另合入原工作台的独有运营内容。契约在 `web/src/types/overview.ts`，状态词汇与管道页共享。
- 一个渠道一条四环节流水线，红灯渠道和问题优先展示，提供下一步。窄屏保留横向流程，在局部滚动区查看；不使整个页面横向溢出。沿用现有 Chip、Skeleton、Empty 和设计变量，新样式放在独立 CSS 中，无外部字体或脚本。
- 数值和时间为空时显示「未知」，已知的 0 保留；时间固定为北京时间并提供相对时间。官方余额从 micros 换算，最多保留六位小数；余额、百炼免费 tokens 不合并。阿里历史显示已保存量、会话量、消息时间范围、月度数量和接口返回的完整性说明。
- 404 显示「接口尚未部署」，500、网络及解析失败显示「读取失败」，刷新失败保留旧结果并明确提示。缺失环节按未知显示，不作为健康；演示数据不会自动替代接口。
- `web/src/fixtures/overview.demo.ts` 全部为虚构数据，包含阿里探针暂停 47 分钟、正常、偏慢和未知状态。浏览器检查使用该夹具拦截接口，不保存或访问真实业务数据。
- `web/e2e/smoke.mjs` 包含桌面与手机总览页面；真实接口 404 只有在明确渲染失败态时才视为预期。另有 22 个隔离场景，覆盖成功、404、500、断网、空值、空记录、未接入、缺失环节、余额精度、刷新失败和加载。

本次使用本地构建静态服务和与演练服务相同的严格 CSP（`script-src 'self'; style-src 'self'`）完成总览隔离浏览器检查，无脚本异常、CSP 报错或整页溢出。`npm run build` 与 `npx tsc --noEmit` 通过；未运行 `tsc -b`。全站真实接口演练、后端接入与生产部署不属于本次验证范围。

复现总览隔离检查（在 `web/`，自动启动 workspace 构建静态服务；CHROME 可选，指向本机 Chromium）：

```sh
npm run build
npx tsc --noEmit
ONLY=overview PLAYWRIGHT_BROWSERS_PATH="$PWD/.browsers" OUT="$PWD/../artifacts/overview" node e2e/smoke.mjs
```

截图在任务 workspace 的 `artifacts/overview/` 中，包括桌面、手机的演示、404 和 500 画面。


## 运营台精简与首页直达（UX1 / UX2 / UX3，2026-11-02，未部署）

信息架构先写入 `docs/web-entrypoints.md`，再实施导航和页面调整。运营台固定九项，后台设置按渠道与数据、设置、整理工具分组。旧工作台在 `/workbench` 保留；独有的待办、成交简报、提醒、待回复、成交结果和资料到期提示复用到总览「今日运营」。原灵感与重复渠道摘要只在保留页展示。

商机沟通沿用共享收件箱三栏，将客户资料放在右栏首位；手机底部可展开资料和 AI 建议。案子按销售阶段分列，仅统计当前页并保留总数与分页，不增加拖动改阶段；客户按最近会话建立时间线，供应商按已有带日期报价建立时间线，无资料则明确说明。视觉继续使用项目既有组件与 CSS。

严格 CSP 下的全页面浏览器检查使用 `web/e2e/local-server.mjs` 与 `fixtures.mjs`，自动创建 loopback 服务，数据全为虚构、未登记请求失败，不连接真实后端、不写生产目录。覆盖桌面和手机共 108 个视图，包括 43 个页面/筛选/保留 URL 各两种尺寸与总览 22 个故障边界场景。导航数量、顺序、分组、旧页保留、三栏和手机资料展开都有断言；手机截图等待抽屉动画结束，防止误拍移动中间状态。截图与具体结果见 `docs/ux-acceptance.md`。

生产根路由只读核查发现 `/` 与 `/v3/` 已跳新版，但密码登录成功绕到 `/v3/workbench`。`patches/ux-root/` 提供两个源码文件的最小补丁、SHA256 基线、隔离测试与回滚说明；不改业务逻辑或认证门。
