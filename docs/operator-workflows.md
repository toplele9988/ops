# 运营操作手册（面向老板的"能干活"标准）

2026-11-02。老板的要求：打开系统就知道今天先做什么，每一步都有按钮，点完有结果，数据自己流转，细节不用他操心。只有"发送给客户/供应商""确认收款"两类动作必须由人点击，其余能自动的都自动或一键完成。

本文件是所有页面与后端任务的验收依据。页面只有文字、没有可点的下一步，视为未完成。

## 一、页面验收的统一规则（每个页面都要过）

1. **一句话说明**：页面顶部一行"这页用来做什么"，用生意上的话，不讲系统。
2. **每条数据旁边有下一步按钮**：例如会话旁"AI 起草回复""转为案子"，案子旁"推进到下一阶段""问供应商"，不能只展示。
3. **空态给出路**：没有数据时说明原因（没接入/还没采到/都处理完了）并给按钮（去接入/去刷新/回总览）。
4. **做完有反馈**：保存、发送、推进之后显示结果和去向（"已记入时间线，案子进入报价阶段"）。
5. **危险动作二次确认且可见后果**：对外发送、确认收款、标记丢单、合并客户。
6. **手机可用**：同样的按钮在手机宽度下能点到。
7. **真实操作验收**：Playwright 脚本必须真的点击完成该页的主流程，并核对接口副作用，不只截图。

## 二、老板的一天（8 条主流程）

### W1 开工：总览 → 今天要做的事
打开首页，顶部是"今天要做的事"队列（待回复买家、要催的供应商、待确认的收款、报价快到期、采集或知识库异常），每一条有一个主按钮，点了直接进入处理页并带着上下文。处理完回到队列，队列减少。

### W2 收到询盘：商机沟通
- 左：会话列表（阿里/微信/WhatsApp），按"要我回复""等对方""已处理"筛选，显示最后一句、等待时长、归属客户。
- 中：完整对话，图片文件可点开，外语消息一键翻译。
- 右：这个人是谁（客户资料卡）、关联的案子、AI 建议。
- 主动作：**AI 起草回复** → 可编辑 → **确认发送**（人点击，走 outbox，测试环境只写草稿不外发）；**转为案子 / 关联到已有案子**；**问供应商**（自动带上客户问题和产品，起草到供应商会话）；**标记已处理/稍后提醒**。

### W3 管案子：案子看板与案子页
- 看板按阶段分列，每张卡显示"卡在谁手上"、下一步、金额。
- 案子页：时间线（跨渠道消息汇总）、参与方（客户/供应商/货代）、待办清单（可勾选）、报价轮、收款。
- 主动作：**新建案子**（从会话或手动）、**推进阶段**（阶段默认待办自动生成）、**生成报价**、**记录客户还价**、**确认收款→成交**（人点击）、**丢单并写原因**。

### W4 管客户：客户列表与客户页
列表可搜索、按国家/来源渠道/最近联系/是否有未结案子筛选。客户页：多渠道身份合并展示、全部往来时间线、案子、备注与标签、下次跟进日期；**新建/编辑/合并重复客户**；**一键跟进**（起草跟进消息）。

### W5 管供应商：供应商列表与供应商页
同客户，另含：产品清单、最近报价与有效期、装箱尺寸毛重核对状态、待询问事项；**一键询价/催资料**（起草到供应商会话）。

### W6 报价与成交
案子里选产品和数量 → 自动取已核准成本和货代运价 → 算 FOB/到门价并提示倒挂和成本过期 → **生成报价单/PI 草稿** → 人确认发送。客户付款后人点击**确认收款**，案子变"已成交"，生成备货待办。

### W7 履约：备货与发货
成交案子进入备货看板：下单给供应商、验货、订舱、发货、签收各节点有按钮和日期；节点超期进入"今天要做的事"。

### W8 知识与 AI 员工
知识检索页可直接把命中的内容"引用到当前回复"或"保存为案子备注"；AI 员工页显示每个岗位最近做了什么、待人确认什么，每条都有"采用/改/拒绝"按钮。

## 三、自动化（不需要老板操心的部分）

- 新消息入库后自动：识别是谁（客户/供应商/货代）→ 归到往来单位 → 判断是否属于已有案子，不确定时放入"待你确认归属"（一键确认）。
- 案子秘书每天生成进展摘要与建议下一步。
- 巡检：久未回复、报价到期、待付款久未到账、物流节点超期，进入"今天要做的事"。
- 数据管道断了（阿里探针暂停、微信无新消息、知识库积压）在总览置顶提示并给恢复步骤。

## 四、全球买家与时间

客户遍布全球，任何时刻都可能有人询盘，系统按 7×24 小时设计：

- 采集、知识整理、巡检、AI 起草不分白天黑夜持续运行，不设"下班静默"。
- 所有时间统一存 UTC，界面默认显示老板所在的北京时间；会话和客户页同时显示**对方当地时间**（按国家/时区），让人判断此刻打扰是否合适。
- "等了多久"一律按真实经过的小时计算，不按工作时间折算；对方深夜发来的询盘排在队列里，早上看到时已有 AI 草稿。
- 提醒与跟进用"对方的上班时间"推荐发送时机，但发送由人决定。
- 总览显示最近一次各渠道收到消息的时间，凭此判断管道是否在 24 小时持续进数据。

## 五、边界

- 对外发送与确认收款永远是人点击；开发与测试阶段不得向真实客户发消息，用演练模式（只写 outbox 草稿，标记 dry-run）。
- 不把真实客户内容写入仓库；测试一律虚构数据。
- 不改网络分流；不碰发品。
