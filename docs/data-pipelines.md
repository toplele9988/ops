# 数据管道与多语言：让数据源源不断地进来

状态：2026-11-01，总指挥（Claude）根据老板口述整理。对应需求账本 H1–H9。

## 1. 老板要的是什么

一句话：**在一个后台里收发阿里国际站、微信、WhatsApp 的一切往来（文字、卡片、商品链接、图片、视频、文件），
语言不再是障碍；有了询盘就能一路推进到客户付款成交。**

拆开说：

1. **收得全**：客户发来的和我们发出去的，包括文字、商品链接/卡片、图片、视频、文件，三个平台都要采集进来，
   并且永远在更新，不能再出现“成交了两单后台没数据”。
2. **看得懂**：客户用任何语言，我都能设成自己要的语言（默认中文）来看。
3. **说得准**：我写给客户的话，不管我用什么语言写，发出去的都是客户的母语；母语要能设置、能自动识别、能手动锁定。
4. **推得动**：来了询盘，系统帮着把获客、产品供应商、物流供应商、其他供应商、客户下单收款这条线跑顺。
5. **只看结果**：我主要看成交；系统出问题要自己发现并告诉我，而不是等我发现数据没进来。

不在本阶段：发品（暂缓）、广告/独立站增长、AI 自动向客户发送（发送、收款确认永远由人点击）。

## 3. 管道一致原则

* **幂等**：同一条消息/同一个文件重复到达，只留一份（按平台消息 ID，文件按 SHA-256）。
* **实时优先、历史补全**：实时条目必须带平台消息 ID 和发送时间；历史导入不覆盖实时。
* **只收不执行**：附件按不透明字节保存，不解析、不执行；URL 只作来源，不自动抓取。
* **来源可追**：每条数据带渠道、账号、到达时间、探针版本、实时/历史标记。
* **断流自知**：每个来源有心跳和“最后到达时间”，超过阈值写明原因和下一步。
* **私有数据不出站**：真实聊天、附件、订单、价格只在 221 的私有目录，不进公开仓库。

## 4. 语言模型

* `my_language`：我的阅读语言，默认简体中文，可在设置页改。
* 每个联系人有 `native_language`：来源优先级为 手动锁定 > 文本识别（置信度足够）> 国家推断（仅作提示）。
* 每个会话可临时指定阅读语言。
* 看：消息默认显示原文，一键显示译文；译文缓存（原文哈希 + 目标语言），同一句不重复调用。
* 说：我用任何语言起草 → 系统产出客户母语版 + 回译成我的语言供核对 → 我确认后才发（阿里走“复制到 Win10 发送”，WhatsApp 走确认发送）。
* 母语未知时：不允许“发送母语版”，提示先确认语言。
* 保护：型号、品牌、数字单位、DMX/RDM/IP 等灯光行业词保持原样；术语表可编辑。
* 翻译调用走国产模型（DeepSeek/Qwen），占独立额度桶，不挤占报价抽取等岗位。

## 5. 阿里国际站采集契约（v2，草案，两侧共同遵守）

当前接收端 `POST /api/inbound/alibaba` 只接受固定字段（account、conversation_id、buyer_name、country、
content、url、message_id、event_id、sent_at、observed_at、history、role、probe_version、live_provenance），
多余字段一律拒绝，正文上限 16000 字、整个请求 64 KB。v2 在此基础上**只加可选字段**，旧脚本照常工作：

* `message_kind`：text / image / video / file / voice / product_card / inquiry_card / order_card / link_card / system
* `attachments`（≤20）：`attachment_id`（稳定ID）、`kind`、`filename`、`mime`、`size`、`sha256`（可选）
* `cards`（≤10）：`card_type`（product / inquiry / rfq / order / link）、`title`、`url`、`product_id`、
  `image_attachment_id`、`price_text`、`moq_text`、`subtitle`
* 文件上传另走一个口：`PUT /api/inbound/alibaba/attachments/{event_id}/{attachment_id}`，请求体为原始字节，
  `Content-Length` 必填，`X-Content-SHA256` 校验，大小上限 50 MB，类型白名单，鉴权同现有入站口；重复上传返回 duplicate。
* 带附件的消息可能先于或后于文件到达；二者按 `(event_id, attachment_id)` 关联。
* **指纹兼容**：新字段不得改变旧消息的去重指纹，否则历史会被重复入库；补发附件信息应更新同一条记录。

Win10 一侧还必须做到：实时消息带平台 `message_id` 与 `sent_at`；心跳每 60 秒一次且包含各类最后捕获时间与错误计数；
遇到登录过期、标签页休眠、页面改版时在心跳里写明，而不是静默停止。

## 5.2 数据留存与知识层

三层，下层永不被上层覆盖：
1. **原始层**：消息 JSON 与附件字节原样保存，按 SHA-256 内容寻址，带来源渠道/账号/到达时间/实时或历史标记；有清单可抽检。
2. **索引层**：会话、联系人、消息、附件、卡片的结构化库（SQLite），供后台页面和检索使用。
3. **知识层**：从资料提炼出的带来源、带时间的事实，供所有 AI 通过知识库检索使用。这是归档、解析、提炼、索引与检索，**不等于训练模型权重**；事实使用前仍须核对来源和日期。
