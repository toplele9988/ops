# 总工程方案：AI 运营的贸易系统

## 1. 目标

**老板只看成交结果。** 询盘进来、问供应商、问货代、算价格、谈判、收款、发货、售后、返单，由系统和各个 AI 配合完成；老板只在几个关键点拍板（报价发出、付款确认、对外发货信息），并每天看一页"成交简报"。

## 2. 一页看懂的结构

```
渠道（阿里 / 微信 / WhatsApp / 以后独立站）
        │  适配器：把消息收进来，必要时代发
        ▼
会话 ──归属──▶ 往来单位（客户 / 产品供应商 / 货代 / 配套供应商）
        │
        ▼
案子（一笔生意） ◀── 报价轮（成本+运费+配套+利润，带有效期）
   │  阶段 · 待办 · 经过 · 产品清单 · 问题与反馈
   ▼
知识中枢（所有 AI 的统一入口）＋ 公司背景与规则
   ▲
AI 岗位：分拣员 · 案子秘书 · 分角色起草 · 核价员 · 巡检员 · 反馈归集员
```

## 3. AI 做到什么程度（自主级别）

| 级别 | 含义 | 例子 | 当前开放 |
|---|---|---|---|
| L0 建议 | AI 只给建议 | 下一步该做什么 | ✔ |
| L1 草稿等确认 | AI 写好，你点确认才发出 | 回复客户、问供应商、问货代 | ✔ |
| L2 自动做内部的事 | 整理、归类、摘要、提醒、算价 | 案子摘要、核价、过期提醒 | 逐批开放 |
| L3 自动对外 | 不经确认发给客户或供应商 | 催一下、确认收货 | **不开放**，等你单独授权、且先在小范围试 |

钱和对外发出的内容永远留在 L1：报价发出、收款确认、发货信息。

## 4. 分批工程（每批交付前必须过质量关）

| 批次 | 内容 | 状态 |
|---|---|---|
| 0 质量地基 | 全页面自动冒烟测试；真实数据演练服务；备份与回滚脚本；错误可见 | **本轮** |
| A 渠道与资料 | 三渠道收件箱、富消息、知识中枢、供应商/产品/货代档案、案子地基 | 已完成，持续修补 |
| B 报价与核价 | 报价轮、成本构成、有效期检查、倒挂检查、还价记录、报价文本 | 已上线（2026-10-29） |
| C AI 岗位 | 案子秘书、分拣员、分角色起草、核价员、巡检员；AI 员工页；成交简报 | **下一批** |
| D 资料补全 | 报价表读行生成产品；货代群运价抽取；新群与联系人分类；标记忽略 | 之后 |
| E 履约与售后 | 下单、验货、发货节点、收款确认、PI/装箱单、问题与反馈转厂家、返单 | 之后 |
| F 渠道补全 | 阿里 5 个子账号、WhatsApp 扫码入口与媒体、阿里附件、微信发送（需授权）、独立站 | 之后 |
| G 团队与报表 | 子账号分工、成交与利润报表、供应商表现 | 之后 |
| H 增长 | 阿里发品、直通车、独立站广告 | 最后 |

每一批都按同一套流程：设计 → Codex 写后端与测试 → 我写前端 → 审查 → 真实数据演练 → 自动冒烟 → 上线（备份、回滚）→ 你验收。

## 5. 防 bug 的机制（"做出来不能用"的对策）

1. **单一需求账本**：你说过的每句话都在「需求与验收」里，有编号、现状、怎么验收。
2. **四层测试**：虚构数据自动测试 → 真实数据只读演练 → 真实浏览器全页面冒烟（本轮新增，`scripts/e2e_smoke.sh`）→ 你的验收。
3. **页面冒烟的判定**：每个页面能打开；没有浏览器报错；没有接口 4xx/5xx；没有"没能读到…"这类错误空状态；关键内容出现。**任何一项不过，不上线。**
4. **真实案例走查**：每批用你自己的一笔真实生意走一遍，由你说对不对。
5. **上线纪律**：先备份、再装入、核对路由表、再重启；库升级要先备份并主动迁移；保留回滚。
6. **不会用的对策**：每个页面空状态说清下一步；术语用你的说法；危险动作有确认；同一个动作在各页叫同一个名字。
7. **发现 bug 不藏**：记进需求账本"已知问题"，下一批必修。

## 6. 你的角色

- 平时：看工作台和成交简报；
- 关键点：点"确认发送"、"确认收款"；
- 每批：用一笔真实生意验收，告诉我哪里不对。
