# 乐初运营系统总纲（唯一权威，所有 AI 开工先读）

2026-11-02 立。本文件与 `docs/project-status.md`（当前进度）、`web/src/data/requirements.json`（需求账本）三者为准；其他文档是历史或细节，与本文件冲突时以本文件为准。改动本文件须老板同意。

## 1. 目标

舞台灯具外贸。系统把阿里国际站、微信、WhatsApp、网易外贸通、独立站、社媒的数据汇到一处，AI 认清每个客户、供应商、产品，替老板备好每一步（回复、问价、报价、跟进），老板只看、改、点发送，最终看成交（客户付款）。

## 2. 生意模型（所有数据都要落到这几类上）

**往来单位**，一个单位可有多个渠道身份（同一人的阿里、微信、WhatsApp 归到一处）：

| 大类 | 细分 |
|---|---|
| 客户 | 工程客户、批发/经销客户、终端使用客户、其他（可增） |
| 供应商 | 产品供应商、物流（货代）、配套（包装、认证、验货、报关、打样等） |

**产品**：品类 → 型号 → 配置/变体。不同供应商的同款要识别为重复并合并，保留每家的报价。

**价格**：
- 供应商报价是零散的，只报了问到的几款。每条报价记录：哪家、哪款、什么配置、多少钱、什么条件、哪天报的、出处（哪条消息或哪份文件）。缺的就标"未报价"，不猜。
- 对客报价按客户类型不同：工程、批发、终端各有规则。

**案子**：一笔生意，从询盘到付款、发货、售后、返单，详见 `docs/deal-design.md`。

## 3. 数据怎么联动

```
各渠道 → 统一消息库 → 认出是谁（往来单位） → 档案（客户/供应商/产品/价格） → AI 工作 → 运营台
```

- 新渠道只需要做一个"适配器"把消息和文件送进统一消息库，后面全部复用。
- 档案是知识库的核心：每个客户、供应商、产品一份，带来源，持续更新。零散的"消息事实"不是目标。
- 供应商发的微信笔记、Word、Excel、PDF 都进档案，由 AI 拆成产品与报价条目。

| 渠道 | 现状（2026-11-02） | 怎么接 |
|---|---|---|
| 微信 | 每天数据最多，供应商都在这里；正常采集 | 第三方商业 API |
| 阿里国际站 | 主要客户来源。只有聊天约 1.4 万条，采集暂停中；订单、询盘、客户、发品记录、推广数据都还没有 | 没有可用接口、导出有限，只能由 Win10 的 Codex 桌面版写采集器读已登录页面 |
| WhatsApp | 消息很少 | 开源 WAHA |
| 视频号 | 有采集项目 | 开源项目 |
| 网易外贸通 | 刚开通，未接 | 待查其接口或导出 |
| 独立站、社媒 | 未建 | 以后接 |

## 5. 规矩：只留真正的红线

**红线（不变）**：
1. 对外发送按"分级自动"（老板 2026-11-02：要 AI 像真人一样在微信、WhatsApp、阿里里回复客户、找供应商要资料、问运费、算利润报价、起草订单、安排发货）：
   - 第 1 级（先开）：对供应商、货代自动发要资料、问价、问运费、催交期；不下单、不谈付款。
   - 第 2 级：对客户自动回复常规问题（产品资料、规格、交期、跟进），内容只用已核实档案；AI 草稿老板连续两周基本不改再开。
   - 第 3 级：报价、PI、订单、发货安排由 AI 起草，老板一键确认后发出；准确率稳定后可按客户逐个放开。
   - 确认收款永远由老板点击。每级、每个联系人都可单独开关，总开关一键全停。
2. 不给客户发测试消息；自动发送上线前先在演练模式跑，老板看过记录再开。
3. 网络分流（代理、路由、防火墙、DNS）只读，改动要老板单独同意。
4. 客户聊天、价格、账号等私有数据不进公开 GitHub。
5. 阿里登录留在 Win10，不导出 Cookie、令牌。
6. 发品（往阿里或独立站发布商品）要老板审核后再发。

**过去 AI 自己加的、建议放宽的**（老板确认后生效，确认结果记在下方）：

| 规矩 | 问题 | 建议 |
|---|---|---|
| 知识库每轮只处理 2 条，遇任何未知就停 | 一小时只处理 5 条，积压 2300 条 | 常驻运行，按免费额度放量；单条失败跳过并记录，不整体停 |
| 知识库按"单条消息找事实" | 结果多为空 | 改为按客户、供应商、产品建档 |
| Codex 桌面版不准点"导出/下载"、不准翻阅阿里后台页面 | 两年数据拿不回来 | 允许只读浏览、翻页、点开详情、点导出/下载；仍不准点回复、发送、修改、删除 |
| 阿里历史不准大量补采 | 订单、询盘缺失 | 允许低频全量补采，避开风控 |
| 每次改动都要老板运行 sudo 命令 | 进度卡在老板身上 | 业务服务（不含网络）允许 Claude 直接安装与定时运行 |
| Claude 不准提交 GitHub | 线上仓库停在 10-28，后面 170 多个文件没保存 | 每个里程碑脱敏后提交推送 |

## 6. 里程碑（一次只推一个，前一个验收了再下一个）

| | 里程碑 | 老板能看到的验收 |
|---|---|---|
| M1 | 阿里数据全量回家 | 系统里能查到两年来每个阿里客户的询盘、聊天、订单、成交与否；新询盘 5 分钟内进来 |
| M2 | 档案建成 | 打开任一客户、供应商、产品，看到 AI 整理好的档案和每条来源；供应商重复品类已合并 |
| M3 | 询盘到成交主线 | 真实新询盘进来，系统已认出客户、备好回复和问供应商的话、算好报价，老板点发送 |
| M4 | 选品与独立站 | AI 按档案和阿里成交数据推荐上架产品，生成独立站商品资料，老板审核发布 |
| M5 | 新渠道 | 网易外贸通、独立站、社媒接入，同样进统一消息库和档案 |

现在推进：**M1**。M1 期间微信、WhatsApp 照常采集，M2 的供应商资料整理可并行（数据已在 221）。
