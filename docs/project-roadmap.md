# 乐初业务运营系统：产品目标与开发路线

本文是供项目协作使用的公开版需求索引。真实运行状态、业务资料和历史对话保存在授权环境中；本文件中的目标不等同于已经上线或验收的功能。

## 产品目标

建立统一的业务工作台，让团队在同一系统内处理客户沟通、客户资料、产品和供应商资料、报价及订单；把业务过程中的消息、文档、图片、视频和经验整理为可追溯、可搜索的知识，供业务人员和 AI 使用。

- 运营前台覆盖多渠道会话、客户跟进、产品、供应商、报价和订单；系统管理与日常运营分开。
- 渠道包括微信、阿里国际站、WhatsApp、独立站及 Gmail，并预留其他平台适配能力。每个渠道分别核验接收、历史资料、附件和回传能力。
- 初期两位使用者业务权限相同，支持账号密码登录和内网与外网访问；账号设置放在系统管理页面，实际可用性以部署验收为准。
- AI 辅助理解客户需求、检索产品和供应资料、生成建议与草稿，逐步支持经配置的运营回复与原渠道发送。发送状态未知时应先核对，避免重复发送。
- 支持按任务使用 Qwen、DeepSeek、Claude Code 和 Codex；团队成员可通过内部微信私聊自然语言安排任务，结果按原会话回传。网页端 Claude 需要显式提供相关资料，不能假定可以访问本地文件。暂不使用 Gemini。
- 公开视频学习资料可提炼为界面布局、交互动画、工具与工程方法候选，标明来源和适用性，经验证后用于开发；模型提炼与索引不代表模型权重训练。

## 分阶段验收

1. **持续采集和知识积累**：分别验证各渠道接收、去重、来源关联、附件归档、解析和检索；展示失败和覆盖范围。
2. **客户跟进工作台**：按客户查看会话、资料、跟进状态与 AI 建议，支持检索和明确的人机协作。
3. **原渠道回传**：针对每个已接入渠道分别实现和验证草稿、发送结果、失败处理和重复发送防护。
4. **报价与订单**：贯通产品、供应商、物流、报价及订单状态，并保留数据来源与历史版本。
5. **邮箱和独立站**：完成真实授权、收件、发送及历史记录关联；后续平台使用相同适配契约扩展。
6. **质量与运行**：建立基于真实使用场景的检索、回答和页面流程测试，监控服务、处理进度、失败项及模型消耗。
