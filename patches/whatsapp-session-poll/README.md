# WhatsApp 会话轮询候选补丁

本目录的 SHA-256 是本工作区修改前的文件基线，不宣称是生产文件哈希。`bridge.patch` 与 `pipeline.patch` 分别对应桥接和健康规则；文档和虚构测试在工作区相应目录。应用前先在目标源码副本核对 `sha256sum -c patches/whatsapp-session-poll/baseline.sha256`，不一致时人工合并；在副本使用 `patch -p1 --dry-run` 分别检查两份补丁。实际 WAHA 的状态接口契约尚未确认，参见 `docs/whatsapp-login.md`；本交付没有部署或验证真实服务。

回滚时优先恢复同一次变更前备份的三个源码文件，并按实际服务变更流程恢复进程；若文件没有其他并行修改，也可在源码副本使用 `patch -R -p1 --dry-run` 检查后分别反向应用两份补丁。回滚后原有 events 内的轮询记录仍是不可变归档，直到超过健康证据时限仍可能作为普通状态事件被旧规则读取；不得删除或修改这些记录。旧规则还会把轮询 FAILED 计入 24 小时失败统计，且最后 WORKING 等历史字段可能继续包含这些记录。若需保留来源区分和原事件统计口径，应继续保留新版 pipeline 读取规则；仅等待证据过期不足以还原全部历史口径。回滚不需要更改 WAHA 配置或网络。
